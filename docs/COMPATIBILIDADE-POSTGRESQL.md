# PostgreSQL do laboratório

## O que foi verificado

O projeto mantém Java 17, Spring Boot 3.3.4, Hibernate **6.5.3.Final** e JDBC PostgreSQL **42.7.4**. O módulo `hibernate-community-dialects` usa `${hibernate.version}`, a mesma versão gerenciada pelo Spring Boot. Não foi necessário substituir o framework.

O dialect padrão do Hibernate 6.5 exige PostgreSQL 12 ou superior. Na execução real com **PostgreSQL 9.6.24**, a versão anterior falhou ao criar as tabelas: `ERROR: syntax error at or near "generated"`. O SQL era `id bigint generated by default as identity`; PostgreSQL só oferece identity a partir do 10.

O `PostgreSQLLegacyDialect` ajuda a adaptar consultas, mas nessa versão ainda reutiliza `PostgreSQLIdentityColumnSupport`, que emite identity. Por isso, `config/PostgreSqlEscolaDialect` especializa somente essa parte: antes do PostgreSQL 10 cria `bigserial`; no moderno mantém identity. As entidades continuam com `GenerationType.IDENTITY`, as tabelas e as sequências continuam com seus nomes originais. Não há migração destrutiva.

Fontes para conferir a decisão:

- [Matriz Hibernate 6.5](https://docs.jboss.org/hibernate/orm/6.5/dialect/dialect.html)
- [Dialect comunitário 6.5.3](https://github.com/hibernate/hibernate-orm/blob/6.5.3/hibernate-community-dialects/src/main/java/org/hibernate/community/dialect/PostgreSQLLegacyDialect.java)
- [Suporte de identity 6.5.3](https://github.com/hibernate/hibernate-orm/blob/6.5.3/hibernate-core/src/main/java/org/hibernate/dialect/identity/PostgreSQLIdentityColumnSupport.java)
- [Documentação do JDBC](https://jdbc.postgresql.org/documentation/)

## Teste real e limites

Em 05/11/2026 os testes foram executados em instâncias descartáveis PostgreSQL **9.6.24** e **16.4**, em Linux x86_64. A CI usa as mesmas imagens. Isso demonstra compatibilidade do UpBox nessas versões, não suporte oficial do Hibernate padrão ao servidor antigo. PostgreSQL 9 está fora de suporte; outra versão 9.x do laboratório precisa de validação própria. Confirme `SELECT version();` no pgAdmin.

`mvn clean test` preserva os testes rápidos em H2. `mvn -Ppostgres-it verify` também executa:

- `PostgresIT`: concorrência, rollback de saldo/histórico/auditoria, unicidade e administração concorrente;
- `PostgresMvcIT`: IDs e relacionamentos em cadastros reais, BCrypt, login por e-mail, sessão, CSRF, permissões, inatividade, entradas/saídas, data/hora, dashboard e seis relatórios com filtros;
- `PostgresReinicioIT`: fecha e abre a aplicação no mesmo banco, com update e depois validate, confirmando conta, IDs, saldo e histórico preservados.

Todos esses testes usam somente **upbox_test**. O código rejeita outro nome antes de iniciar JPA. Nunca aponte testes destrutivos para upbox ou outro banco de uso.

Exemplo PowerShell, com banco descartável previamente criado:

```powershell
$env:UPBOX_TEST_DB_URL = 'jdbc:postgresql://localhost:5432/upbox_test'
$env:UPBOX_TEST_DB_USER = 'postgres'
$env:UPBOX_TEST_DB_PASSWORD = 'SENHA_SOMENTE_DO_BANCO_DE_TESTE'
mvn -Ppostgres-it verify
Remove-Item Env:UPBOX_TEST_DB_PASSWORD
```

Docker é usado pela CI e pela homologação do desenvolvimento, e não é obrigatório para instalar o UpBox na escola. Faça backup antes de atualizar qualquer banco existente. Não apague tabelas para corrigir conexão, índices duplicados ou versão incompatível.
